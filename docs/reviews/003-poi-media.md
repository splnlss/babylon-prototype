# POI player and placement plan review

**Scope:** [BabylonJS plan](../superpowers/plans/2026-09-30-poi-media.md) for two POI triggers, one video/audio player, and a crude desktop placement tool that downloads JSON. The [approved design](../superpowers/specs/2026-09-30-poi-media-design.md) contains later work beyond this slice.

**Independent review:** Claude reviewed the narrowed plan, current repository, and later JSON-placement addition in [Conductor session](conductor://workspace?id=14cbd485-a488-49e5-b794-f2c469566718&session=3421568c-3530-4f69-92f3-09a4a37f3ca5). It made no edits and requested no external Mux, R2, or Ronda media. Codex incorporated its findings below.

## Findings and disposition

1. **Medium — overlap behavior omitted.** Initial nearest selection and stable replacement after dwell plus a margin were absent. **Fixed in plan:** `PoiTracker` emits replacement and tests an overlapping fixture with a provisional 0.25-unit margin.
2. **Medium — placement data needed one format.** The first narrow draft hardcoded two POIs while the requested placement tool needed JSON export. **Fixed in plan:** runtime loads a validated `src/pois/ronda.json`; the tool edits an in-memory copy and exports that same schema. Full import/add/delete remains out of this slice.
3. **Low — floor height had no file owner.** Current config holds eye Y=5 but no walking-floor value. **Fixed in plan:** calibrate and add `POI_FLOOR_Y` in `src/config.ts`.
4. **Medium — editor and video click handlers could conflict.** Both tasks modify `src/desktop.ts`, and the click precedence was undefined. **Fixed in plan:** one `attachDesktopControls` input gate handles editor, active video/retry, then pointer lock.
5. **Medium — duplicate live and draft markers.** Editor preview could render a second marker set over the committed one. **Fixed in plan:** editor mode swaps live markers for draft markers; XR uses committed markers and restores the draft on exit.
6. **Low — editor placeholder could be picked as video.** **Fixed in plan:** placeholder is non-pickable and the picker targets only active video/retry surfaces.
7. **Medium — Babylon video engine extensions.** The local WebGL2 spike initially raised `createDynamicTexture` and `updateVideoTexture` missing-method errors with direct module imports. **Fixed in plan:** explicitly import the two Babylon engine extensions; the final local clip ran to `ended` with no page errors.
8. **Medium — external video probe lacked a byte cap.** Claude's independent pre-build review found the 15-second playback limit insufficient to bound transfer cost. **Fixed in pre-build package:** stop at 15 seconds or 5 MiB of completed video transfers, abort active requests, and record in-flight overshoot. Audio checks now specify byte ranges and a 512 KiB abort threshold.
9. **Low — HLS dependency not named in pre-build decisions.** **Fixed:** the package proposes exact `hls.js@1.7.3` (Apache-2.0) for owner confirmation.

## Implementation review and disposition

Claude independently reviewed the uncommitted implementation in [Conductor session](conductor://workspace?id=14cbd485-a488-49e5-b794-f2c469566718&session=65de118e-1e8f-4917-b098-23b5350ca53c), including installed Babylon 9.28.0 source and throwaway probes outside this repository. It ran `npm run check` (40/40 at its snapshot), `npm run build`, and `git diff --check` without editing the repository or requesting public media. Its findings below continue the numbering above. Codex applied the fixes and reran checks; a separate read-only verification of those fixes was requested from Claude.

10. **Medium — status plane too close to the visitor's eye.** Claude measured the original 1.8 × 0.45 plane just 0.2 units from the eye at a POI centre, obscuring the video and risking XR discomfort. **Fixed:** `PoiScene.updateStatusPose` follows the head at 1.8 units forward, 1 unit to the right, and 0.65 below, with a 0.8 × 0.2 plane. A geometry test checks the eye distance and separation below the video plane. Headset appearance remains unverified.
11. **Medium — editor mode blocked walking and turning.** The original walk gate required a focusable canvas, but the canvas has no `tabindex`, so capture buttons could only use the spawn pose. **Fixed:** WASD walking now works unless an editor field is focused; Q/E turn without pointer lock. A happy-dom input test and Chrome editor walk check captured source Z=39.4 after movement from spawn Z=40, with no pointer lock or media request.
12. **Low–medium — missing interaction tests.** Claude identified no direct tests for the editor input gate or DOM draft preview. **Addressed:** added `tests/desktop.test.ts`, `tests/poiEditorUi.test.ts`, and a status-pose assertion in `tests/poiScene.test.ts`. Full XR exit and scene-retry browser paths still require device or manual acceptance checks.
13. **Low — unsupported host scale could become a scene error.** `resolvePois` threw inside scene loading and some render/editor paths. **Fixed:** `tryResolvePois` yields zero POIs plus a separate POI warning, and `main.ts` caches resolved live POIs so the per-frame path is throw-free. A non-unit host test covers the warning path.
14. **Low — terminal audio status persisted after exit.** Ended or failed audio kept an old status and could be retried after the visitor left. **Fixed:** audio exit clears terminal state while ordinary playing audio still continues after walk-away; a lifecycle test covers error then exit.
15. **Low — unlocked pick coordinates would be scaled twice if hardware scaling changed.** **Fixed:** pass raw canvas-relative client offsets to Babylon's picking-ray method.
16. **Nit — near-vertical plane placement passed the horizontal guard.** **Fixed:** check horizontal length before normalizing; a test rejects an almost vertical look.
17. **Nit — unused `PoiScene.isSelectable`.** **Fixed:** removed it; `selectableMeshes` remains the sole pick target list.

The final local check after these fixes passed TypeScript and **47/47 tests in 11 files**; `npm run build` and `git diff --check` passed. Headless Chrome loaded visitor and editor modes with zero page errors and zero Mux/R2 requests before arrival. A route-intercepted video arrival requested the expected Mux master URL and showed a media error, without sending it to Mux. The editor downloaded valid JSON, stayed unlocked, and captured a moved location. The earlier approved bounded probe established one Mux video frame and sampled audio-only AAC, but not full audio playback or Quest behavior. Claude's full independent review preceded fixes 10–17. Its follow-up session and a fresh Sonnet verification session both hit the account's usage limit before reviewing those fixes; independent verification of the final diff remains pending.

## Final merge review and disposition — 2026-10-01

Claude independently reviewed current HEAD plus the owner-directed uncommitted changes against `origin/rabat` in [Conductor session](conductor://workspace?id=14cbd485-a488-49e5-b794-f2c469566718&session=57f95de7-8f87-43d2-b24f-18fff11bb2d0). Its read-only review ran `npm run check` (53/53), `npm run build`, `git diff --check`, and a Babylon `NullEngine` geometry probe. It requested no external media and found two confirmed merge blockers. Codex reproduced both in failing tests, fixed the code, and requested a follow-up read-only review in the same session.

18. **Medium — pointer-locked desktop could not reach blocked-media Retry.** The head-following status plane sits off the forward centre ray, while locked clicks used that ray; the removed page media control left blocked audio with no practical retry. **Fixed:** locked desktop clicks retry blocked/failed media when the ray misses the selectable plane. Unlocked desktop and XR still require a target hit; playing video still toggles only on a hit. A `NullEngine` selection test reproduced the missed off-axis target before the fix and passes after it.
19. **Medium — blocked audio remained active after exit.** `MediaPlayer.exit()` stopped audio only after ended/error, so a denied `play()` left the source and status active away from the POI and reentry could not start a fresh source. **Fixed:** blocked audio now stops on exit; a lifecycle test reproduced the old state and verifies teardown plus fresh reentry. Playing audio still continues on walk-away.
20. **Low — centre reticle absent.** The owner's later instruction explicitly limited the normal page to the scene and Enter VR button. **Accepted owner override:** no reticle on the page.
21. **Low — warnings moved off the normal page.** Same owner instruction. **Accepted owner override:** scene load errors retain Retry; other warnings are available in the console and review documentation.
22. **Nit — status-plane side variable named `right` while Babylon's cross product points left in this coordinate setup.** Geometry and functionality are unaffected; the name remains a minor readability issue.

After fixes, `npm run check` passed TypeScript and **55/55 tests in 11 files**; `npm run build` and `git diff --check` passed. The build emits the existing large-chunk advisory. These checks do not establish full external-media playback, XR controller selection, visual comfort, or headset performance. The owner later specified camera world Y=3.6 and interaction floor Y=2 while keeping 1.6 units of eye height; the latest draft was desktop-reviewed at those coordinates. Because the code changed after that draft, it must be replaced by a newly validated draft before live publication.
