# BabylonJS POI media player — Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans task by task. Follow repository `AGENTS.md`: do not commit, push, or open a PR automatically.

**Goal:** In the existing BabylonJS Ronda scene, play video or audio when a visitor reaches a POI, and provide a crude desktop tool to place the POIs/video plane and download their JSON.

**Architecture:** Keep the current SOG stream, camera, locomotion, and XR render helpers. Load two POIs and a video-plane pose from a checked-in JSON file; a small proximity controller drives one HTML media session. The desktop placement view edits an in-memory copy and downloads JSON for review, without playing media.

**Tech Stack:** Current BabylonJS 9.28.0, TypeScript, Vite, Vitest; after pre-build approval add exact `hls.js@1.7.3` for Mux HLS where supported.

**Spec:** [Approved design](../specs/2026-09-30-poi-media-design.md). This is the **player, trigger, and crude placement slice** of that broader design. It implements the player behavior in criteria 1–6 and a small part of criterion 7: positioning the two POIs and video plane and exporting JSON. Full editor import/add/delete and full Quest performance sign-off remain later work; this slice does not claim those criteria complete.

**Owner-directed implementation update, 2026-10-01:** The later source and placement instructions supersede the original Y=5 eye and provisional POI coordinates below. Current camera start is `(2.5, 1.2, 24)`, body floor Y=`-0.4`, and the checked-in POI poses are listed in `src/pois/ronda.json`. The video uses the owner's Bob Mux playback ID. Marker labels and the top-left VR pill follow the supplied reference image. Keep the original plan's lifecycle and interaction checks; review the new placement on a device before publication.

## Global Constraints

- Use the Ronda SOG already loaded by `src/main.ts`; keep `src/config.ts:MANIFEST_URL`, `stream.rotation.x = 0`, XR movement, and stereo splat helpers.
- Two POIs: one video, one audio. Entry 0.8 scene units after 250 ms; exit 1.1; vertical tolerance 0.6. On overlap, choose the nearest eligible POI initially; replace it only after the nearer POI's own dwell and a provisionally 0.25-unit distance advantage. At most one media player is active.
- The old design's POIs were placed at Y=0 for a different renderer. This viewer pins desktop eye Y=5 and retains the SOG loader's Y reflection. Map positions near the **actual walking floor** before checking in the two POIs; obtain owner approval for any changed visible placement. Do not assume scene units are surveyed metres.
- Use only the supplied public Mux video ID and either the Mux audio ID **after audio-only validation** or the supplied R2 M4A alone. A Mux stream with video must never be used for the audio-only POI. Do not request external media until separately approved.
- Inactive POIs make no media request. Stop the old source before activating a new one. Autoplay rejection offers a tap/select retry on the same source; fatal failure of a verified Mux audio source tries R2 once.
- `?poiEditor=1` is desktop only. It edits an in-memory draft, previews markers and a solid video rectangle, suppresses pointer lock and proximity playback, and downloads a versioned `.json` file. It does not save to the repository, browser storage, or a server.

## Review Focus

1. Reflective SOG host and current body-floor height: markers, standing radius, and video plane must be reachable and correctly oriented (Task 1).
2. Babylon `VideoTexture` must not silently loop, mute, or call `play()` outside the player; ending and blocked autoplay must work (Task 2).
3. Rapid exit, replacement, scene retry, and `pagehide` must not leave a hidden stream playing (Task 2).
4. Desktop pointer lock and XR controller selection must produce one video toggle per action (Task 3).
5. XR retry feedback must be visible inside the headset, and Quest controller selection must actually unblock `play()` before claiming that path works (Task 3).
6. Placement export must preserve the source-space POI/plane pose and make no media request (Task 4).

## Task 1: Two POIs and arrival trigger

**Files:** `src/config.ts`, `src/pois.ts`, `src/pois/ronda.json`, `tests/pois.test.ts`, `src/main.ts`.

**Interface:** `parsePoiManifest(input: unknown, activeAssetUrl: string): PoiManifestV1`; `resolvePois(manifest, hostMatrix): Poi[]`; `new PoiTracker(pois, replacementMargin)`; `PoiTracker.update(bodyWorld, nowMs): PoiEvent[]`; `PoiTracker.reset()`. `PoiEvent` is `enter(id)`, `exit(id)`, or `replace(oldId, newId)`. The JSON has `version:1`, the exact `assetUrl: MANIFEST_URL`, one video POI, one audio POI, source-space positions, and the video plane's source-space position/rotation/width/height. Validate the version, asset URL, unique IDs, finite pose numbers, ordered positive radii, HTTPS fallback, and positive plane dimensions before showing POIs. A different asset gets zero POIs. Add `POI_FLOOR_Y` to `src/config.ts` from the approved scene calibration; desktop uses camera X/Z plus it, XR uses its rig floor. Avoid eye height for the vertical check.

- [ ] Write failing tests for JSON version/asset/pose validation, the two mapped world positions, 249/250 ms arrival, 0.8/1.1 thresholds, 0.6 vertical rejection, no duplicate entry, nearest initial choice, stable overlap replacement after dwell and the approved distance margin, and reset on scene reload. Use an overlapping fixture because the shipped POIs are far apart. Include a translated reflective host fixture so a forward/inverse mapping bug fails.
- [ ] Run `npx vitest run tests/pois.test.ts`; expect failure. Implement the POIs and tracker; run the focused test and `npm run check`; expect passes.

## Task 2: One media player

**Files:** `src/media.ts`, `tests/media.test.ts`, `src/poiScene.ts`, `package.json`, lockfile.

**Interface:** `MediaPlayer.activate(poi)`, `exit(id)`, `toggleVideoFromGesture()`, `retryFromGesture()`, `stop()`, `dispose()`, `subscribe(status)`. Use one generation token to ignore stale promises/HLS events. Audio continues on exit; video stops and its plane disappears on exit/end. Starting another POI stops the old player first. Scene reload and `pagehide` call `stop()`.

- [ ] Write failing tests for one active session, audio walk-away/re-entry, video exit/end, source replacement order, blocked autoplay retry, fatal Mux-audio-to-R2 fallback once, and late callbacks after stop. Use fake media elements; tests must not request public URLs.
- [ ] Run `npx vitest run tests/media.test.ts`; expect failure. Implement HLS.js first when supported, native HLS otherwise; use `preload='none'`, no inactive attachment, `autoStartLoad:false`, `playsInline`, `loop=false`, `muted=false`, and no timeline. The coordinator alone calls `play()`/`pause()`. Treat `NotAllowedError` as retryable on the same source; ignore superseded `AbortError`; use R2 only for a fatal verified audio source failure.
- [ ] Create the video plane only for active video. Its `VideoTexture` uses `independentVideoSource: true`; explicitly import Babylon's `engine.dynamicTexture.js` and `engine.videoTexture.js` extensions when using the direct `Engine` imports in this app. The local WebGL2 spike hit missing-method errors without them. On stop dispose texture/material/mesh, stop HLS loading, pause and clear the element source, and remove listeners. Run focused tests and `npm run check`; expect passes.

## Task 3: Select video and show status
